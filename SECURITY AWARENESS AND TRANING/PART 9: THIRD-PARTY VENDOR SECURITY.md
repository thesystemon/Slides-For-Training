## **PART 9: THIRD-PARTY VENDOR SECURITY (10 Slides)**

**Slide 1: The Hidden Risk: Vendors & Third-Parties**
* 60-70% of data breaches involve a third-party
* Vendors, contractors, and partners can be targets
* Your organization's security depends on external collaborators
* Real example: Target breach via HVAC vendor

**Slide 2: Types of Third-Party Risks**
| Risk Type | Description | Example |
|-----------|-------------|---------|
| Access Risk | Vendor has access to sensitive systems | Cloud provider admin access |
| Data Risk | Sharing data without protection | Sending PII via unencrypted email |
| Compliance Risk | Vendor violates regulations | GDPR violations |
| Operational Risk | Vendor downtime affects operations | Payroll system unavailable |
| Social Engineering | Vendor tricked by attackers | Fake invoice or phishing |

**Slide 3: Best Practices for Third-Party Security**
* Conduct risk assessments before onboarding new vendors
* Use contracts and NDAs specifying security responsibilities
* Limit vendor access to least-privilege needed
* Regularly review access and revoke when unnecessary
* Ensure vendors follow company-approved tools and policies
* Monitor vendor security compliance regularly

**Slide 4: Vendor Risk Assessment Process**
1. **Pre-engagement:** Security requirements in RFP
2. **Due Diligence:** Review vendor security controls
3. **Contracting:** Include security SLAs and penalties
4. **Onboarding:** Provide minimum necessary access
5. **Monitoring:** Regular security reviews and audits
6. **Offboarding:** Complete access revocation

**Slide 5: Secure Communication & Data Sharing**
* Use company-approved channels for sensitive data (encrypted email, secure portals)
* Avoid personal email, cloud drives, or chat apps for vendor communication
* Verify all vendor requests for access or payment changes
* Use secure file transfer protocols for large data exchanges
* Encrypt all sensitive data shared with vendors

**Slide 6: Detecting Vendor-Related Attacks**
* Common scenarios: fake invoices, impersonated vendor emails, malicious files
* Check sender email domains carefully
* Verify phone numbers through official sources
* Confirm unusual requests with account managers
* Be suspicious of last-minute payment changes
* Encourage reporting of any suspicious vendor communication

**Slide 7: Contract & SLA Security Requirements**
* **Data Protection:** Encryption requirements, data handling procedures
* **Access Control:** MFA, least privilege, regular reviews
* **Incident Response:** Notification timelines, cooperation requirements
* **Compliance:** Regulatory requirements, audit rights
* **Business Continuity:** Availability guarantees, backup procedures
* **Termination:** Data return/destruction, access revocation

**Slide 8: Vendor Security Monitoring**
* Regular security assessment questionnaires
* Review of vendor security certifications (ISO 27001, SOC 2)
* Monitoring of vendor security incidents and breaches
* Regular access right reviews and recertification
* Performance against security SLAs
* Annual security review meetings

**Slide 9: Third-Party Security Checklist**
- [ ] Conduct security assessment before engagement
- [ ] Include security requirements in contracts
- [ ] Limit vendor access to minimum necessary
- [ ] Use secure channels for all communications
- [ ] Verify all payment and access change requests
- [ ] Monitor vendor security compliance regularly
- [ ] Review and update access rights quarterly
- [ ] Have incident response coordination plans
- [ ] Maintain vendor security documentation
- [ ] Conduct regular security awareness with vendors

**Slide 10: Vendor Management Key Takeaways**
* Your security is only as strong as your weakest vendor
* Due diligence prevents downstream breaches
* Contracts must enforce security requirements
* Continuous monitoring is essential
* Quick response to vendor incidents protects everyone
* Vendor security is shared responsibility
